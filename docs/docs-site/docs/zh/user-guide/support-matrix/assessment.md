# 兼容性评估

兼容性评估引导你逐步收集部署 UCM 前所需的信息：推理引擎及其版本、推理卡以及所 serving 的模型。完成四个步骤后，向导会给出当前组合"兼容"、"需要验证"或"不兼容"的结论。

适合在以下情况下使用：

- 在规划 UCM 交付时，确认目标引擎、推理卡与模型的组合是否在覆盖范围内。
- 目标引擎版本或推理卡未列入[支持矩阵](index.md)时，获得明确的"待验证"结论。
- 在交付前检查清单中记录所收集的组合及其评估结果。

向导由 UCM 开发者维护的兼容性数据集驱动，覆盖内容包括：

- **引擎与版本**：vLLM、vLLM-Ascend 与 SGLang。向导展示每个引擎最新 10 个真实上游发布 tag，并标注 UCM 验证状态：已验证适配的版本为"支持"，暂无验证结论的版本（如 vLLM `v0.30.0`、`v0.28.0`）为"待验证"。rc / post 版本按基础版本归一，`v0.26.0rc1` 视为 `v0.26.0`；更早的版本可通过「其他」输入，并按维护的 tag 清单匹配。
- **推理卡**：支持矩阵中的代表性 CUDA 与 CANN 设备，如 H100、H20、L40、L20、910B、910C。
- **模型**：DeepSeek、Qwen、GLM、MiniMax、Kimi 各家族在各引擎上的集成状态。

未在数据集中的取值可通过"其他 / 未列出"手动输入，对应结论为"待验证"而不是直接拒绝。评估结论仅供参考：它反映的是已记录的兼容状态，不能替代目标环境上的实际验证。
